为什么做这个 mod

手机端 Java 版的世界生成，一直是纯 CPU 在扛

MC Java 版在安卓端运行时，每个区块的噪声计算都走 CPU。C2ME 等优化 mod 主要并行化 CPU 侧工作，但 GPU 仍闲置。本 mod 的思路：把 MC 精确的噪声算法整个搬到 GPU 上算。

现状

CPU 逐点算噪声 → 世界加载慢

PerlinNoise 3D 的 double-double 精确算法在 CPU 上是纯串行浮点预算，区块生成时大量时间花在噪声求值上。

做法

GPU 逐像素算噪声 → 并行取回

FFM → dlopen("libmobileglues.so") → GLES 原生函数 → 现有 EGL context → fragment shader 每像素算 double-double 噪声 → RGBA32F FBO → glReadPixels 回读

真机实测 · 骁龙 8 Elite / Adreno 830 / 12G

核心特性

精度不妥协，安全有兜底

GPU 真接管

mixin 在 get(DDD)F 入口命中缓存即 setReturnValue + cancel，调用方直接拿到 GPU 算出的噪声值；miss 不取消，走原 CPU 路径。

只接管首个被捕获的 3D 服务实例，perms/offsets 全匹配才认

double-double 高保真

GPU shader 内用双精度拆对（two_prod / two_sum）复刻 MC 精确噪声，大坐标稳定复现，拒绝 FP32 降级。

[4.5] maxErr 5.499e-07 · 5 轮 STABLE · 大坐标 1.332e-14

影子模式验收

接入世界生成前，先在游戏内跑完整对拍：GPU 输出与 MC 算法逐点比对，5 轮编译自检 + 大坐标稳定性验证全过才放行接管。

GPU 结果永不盲信 —— 每轮验收闭环

抽检才写缓存

每个预生成区块，每柱 24 层与 CPU 参考比对（阈值 1e-5），全部通过才写柱缓存；整块失败则不写，自动回退 CPU。

失败柱 = 0 · 异常全吞不 cancel

批量柱预生成

按 16×16 柱 × 384 层的块布局一次 GPU 计算整块区域（6 次 draw），渲染线程节流执行，后台预取待生成区块。

mode21 · 2×3 分片 · 128×128 RGBA32F FBO

技术路线

一次区块生成，GPU 内走完

GLES3 路线（非 Vulkan）：FFM 直连 MobileGlues 的 GLES 原生符号，在现有 EGL 上下文里跑 fragment shader，输出经 FBO 回读。

1
FFM 绑定dlopen libmobileglues.so，绑定 GLES 原生函数
2
shader 编译double-double 噪声 fragment shader，编译自检 + 重试兜底
3
批量柱16×16 柱 × 384 层，2×3 分片 6 次 draw
4
FBO 回读RGBA32F 128×128 → glReadPixels 取回
5
抽检比对每柱 24 层 vs CPU 参考，阈值 1e-5
6
写柱缓存通过才写；miss → CPU fallback

安装

三步装好，进世界自动验证

需要手机端 Java 版启动器（Pojav / FCL / Zalith），渲染后端选 OpenGLES / MobileGL（不要 DirectVulkan）。

1

放 mods

把 jar 放进实例的 mods/ 目录，确认同目录有 Fabric API。

渲染后端：OpenGLES / MobileGL
2

进世界

启动后进入任意世界。mod 会在游戏内跑 GPU 对拍验收，自动写 gpu-worldgen-verify.txt 报告。

加载时一次短卡顿属正常验证
3

看报告

游戏目录下检查 gpu-worldgen-verify.txt：全绿（误差 < 1e-6、STABLE）即接管生效。

有问题就把报告发 GitHub Issues
